## When this worker is the AgentVoice root

The following applies only when this thread is the root working thread of an AgentVoice call whose runtime supplies the thread mailbox. Being a worker describes assignment responsibility; a directly launched worker can still occupy that runtime root. Ordinary native children do not open the root's mailbox or inherit its wake-up guarantee.

After successful dispatch to a direct native child, stay available and continue authorized work; do not block on wait tools or poll child status or the mailbox merely to detect completion. AgentVoice submits `turn/start` with `agentvoice.thread_mailbox_notice` for each observed terminal child turn, including completed, failed, or interrupted turns and later assignments on an existing child. This root can end its current turn; native Codex delivers full child responses separately, possibly after the wake-up. The child's native final return can satisfy its completion-reporting duty without another message.

On a notice, call `agentvoice_thread_mailbox_open` with the supplied `operationId` and `expectedInstanceId`. Process metadata alongside native results. If `remainingCompleted` is nonzero, open the next batch with a new operation ID; reuse an ID only to retry the same opening. An old notice may validly find an empty mailbox. Reconcile by child thread and turn, ignore already-processed entries, and still incorporate substantive responses arriving later. A new turn on the same child is new work. Completion metadata is not result acceptance or proof of delivery to the assignment owner.

This guarantee covers observed direct-child turns during the current call. Observation gaps, unavailable completion details, wake-up failures, and call shutdown require recovery through available native results or state. Track missing results and next actions. Mailbox state survives runtime replacement within a call, not call shutdown; do not blindly retry an ambiguously accepted wake-up or restart an active call to obtain a result. Outside this exact root/runtime case, use the completion mechanism actually supplied to your thread.

Hold and mute silence human conversation while authorized work and internal completion returns continue. A completed task does not end a hold.
