# 0067: Trial continuous muted Android input

Accepted 2026-09-14 after the human-run Galaxy S22 trial. The operator authorized landing and closing the item. Extends [0035](0035-native-android-voice-client.md). No server or speaker policy changes.

The pinned Android WebRTC fork stops ADM recording when all send streams are muted. Exact cached ARM64 disassembly confirms this branch and its enabled default. AgentVoice previously both zeroed Java input and disabled the local track on microphone mute. Recorded voice answers have appeared tens of seconds after working-agent output; the capture-stop behavior is established, but causality for these delays is unproven.

Keep the active local track enabled while the existing Java ADM microphone mute supplies zero PCM. Pending peers and closed sessions remain disabled. Preserve speaker behavior. This avoids toggling recording for an ordinary mic preference change and leaves local capture active, which can retain Android's microphone indicator and consume capture resources.

The primary [human trial](../../android/MIC-MUTE-TRIAL.md) passed: with the microphone muted, the read-only worker completed at 21:05:02Z and the root spoke its four-project result without requiring unmute. The operator reported “that seemed to work well” and accepted the change. This validates the requested worker-to-root-to-speech behavior in that trial; it does not establish the private remote scheduler's mechanism. Unit tests cover actual gate application, ordering and peer isolation; exact-dependency verification covers zeroing separately. Packet cadence under DTX, direct actual-device PCM inspection, and shared-ADM renewal were not fully audited; these are recorded coverage limits, not additional acceptance gates for the scoped change. Keep a pre-candidate APK for easy recovery. No synthetic agent wake or voice scheduling-mode change is part of this decision.
